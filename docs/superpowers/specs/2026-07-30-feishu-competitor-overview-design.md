# 飞书竞品总览卡片设计

## 背景

当前管线已经完成真实网页采集、快照存储、差异检测和飞书 Webhook 投递，但 `Digest` 只携带统计摘要、变化事件和本地报告路径。首轮基线没有变化事件时，飞书群只能看到候选数、快照数和文件名，无法直接阅读竞品结论。

## 目标

- 一张飞书卡片直接展示本轮最多 5 个竞品的实质内容。
- 每个竞品展示名称、核心功能、套餐价格、关键配置、置信度和官方证据。
- 没有抽取到的字段明确显示“暂未识别”。
- 有效变化仍最多展示 5 条。
- 卡片保持在飞书自定义机器人 20 KB 请求体限制以内。
- Markdown、JSON、CSV 完整报告继续保存全部快照和变化。

## 非目标

- 本次不增强真实定价页的字段抽取算法。
- 本次不把本地报告上传到公网、飞书云文档或云盘。
- 本次不增加前端、交互按钮或多群路由。

## 数据契约

新增严格模型 `DigestProduct`，并同步更新 `schemas/Digest.schema.json`：

- `candidate_id: str`
- `name: str`
- `homepage: str`
- `summary: str`
- `features: list[str]`
- `pricing: list[PriceTier]`
- `configurations: dict[str, Any]`
- `confidence: float`
- `evidence_urls: list[str]`

`Digest` 新增 `products: list[DigestProduct]`，默认空列表并限制最多 5 项，以保持旧调用兼容。

## 摘要构建

`build_digest` 按候选顺序关联 `Candidate` 与 `ProductSnapshot`，生成最多 5 个 `DigestProduct`：

1. 候选名称是 URL 时，使用去掉 `www.` 的主机名作为展示名。
2. 功能最多保留 5 项，每项进行空白规范化和长度截断。
3. 套餐最多保留 3 项。
4. 配置最多保留 3 项。
5. 官方证据 URL 去重后最多保留 2 项。
6. 摘要和所有文本字段做确定性截断，不调用外部模型。

完整快照仍原样写入报告，不受消息截断影响。

## 飞书卡片布局

卡片顺序如下：

1. 标题：`竞品情报基线` 或 `竞品情报更新`。
2. 运行摘要：候选、快照、变化、失败来源数量。
3. 竞品总览：每个竞品一个 Markdown 元素，格式为：
   - 竞品名称及官网链接
   - 核心功能（最多 5 项）
   - 套餐价格（最多 3 项）
   - 关键配置（最多 3 项）
   - 置信度
   - 官方证据链接（最多 2 个）
4. 重点变化：存在确认变化时展示最多 5 条。
5. 本地完整报告路径：作为辅助信息放在底部，不再作为卡片主要内容。

价格、功能或配置为空时分别显示“暂未识别”，避免空白字段。

## 长度控制

- 最多 5 个竞品。
- 每个竞品最多 5 个功能、3 个套餐、3 个配置、2 个证据链接。
- 单项功能和配置值截断至固定长度。
- 摘要文本截断至固定长度。
- 自动测试断言最大边界示例序列化后小于 20 KB。

## 错误处理

- 某候选没有成功快照时，不生成对应 `DigestProduct`，失败来源仍进入摘要和报告。
- 某字段为空时展示“暂未识别”，不推断或虚构数据。
- 某证据 URL 缺失时展示“证据暂未识别”。
- Webhook 传输失败继续返回 `DeliveryReceipt` 并记录运行错误。

## 测试

1. 模型测试：`DigestProduct` 严格校验，`Digest.products` 默认兼容旧调用。
2. 摘要测试：候选和快照正确关联；URL 名称转为域名；字段按上限截断。
3. 卡片测试：直接包含功能、价格、配置、置信度和证据，不再只有报告路径。
4. 空字段测试：价格、配置为空时显示“暂未识别”。
5. 边界测试：超过 5 个竞品和超长字段时确定性截断，请求体小于 20 KB。
6. 回归测试：变化仍最多 5 条，完整报告仍包含未截断快照。
7. 全量测试：覆盖率保持不低于 85%。

## 验收标准

- 使用现有三个真实项目管理竞品运行并强制推送后，飞书卡片直接显示三个竞品的已抽取功能、价格状态、配置状态、置信度和官方来源。
- 卡片正文不依赖打开本地报告即可理解本轮结论。
- 当前未抽取到价格时明确显示“价格：暂未识别”。
- 本地 Markdown、JSON、CSV 报告内容保持完整。
